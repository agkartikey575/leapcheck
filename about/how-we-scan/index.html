How we scan

LeapCheck reads the public code of each plugin version and checks it against the known changes in every PHP version. It never runs plugin code.

What we check

  • PHP compatibility with PHPCompatibility, an open-source rule set built from PHP's official change notes, for PHP 8.3, 8.4 and 8.5.
  • Hidden libraries: copies of other libraries bundled inside a plugin, found by package manifests, file signatures and RetireJS open data (Apache-2.0) for JavaScript.
  • Server requirements: PHP extensions the code appears to use.

Verdicts

  • ✅ Compatible: nothing known to break or be deprecated.
  • ⚠️ Runs, with warnings: deprecated features only.
  • ❌ Errors found: removed or changed features that can stop code working.
  • ❓ Not scannable: encoded or unreadable code.

Limits

Static analysis can't see code that is generated while running, eval, or encoded files, and it can't find a plugin's own logic bugs. A clean result is not a guarantee: always test upgrades on a staging copy first.

Freshness and corrections

New plugin versions are re-scanned automatically. Every result records the engine and rule versions that produced it. If a result looks wrong, report it; plugin authors can request a re-scan the same way.

Open source

The scanner is open source: github.com/agkartikey575/leapcheck.
